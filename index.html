Slide 02

What Are Git and GitHub?

Understanding the difference between the tool and the platform

Git ≠ GitHub

Git (The Tool)

Git is a version control system that runs locally on your computer. It tracks changes to files and allows developers to manage project history completely offline.

GitHub (The Cloud Platform)

GitHub is a cloud hosting service for Git repositories. It provides a web interface, team collaboration, code reviews, and remote backups.

The Relationship Diagram
Your Computer ↓ Git (Software) ↓ Local Repository (.git) ↓ GitHub (Online Cloud) ↓ Remote Repository (Origin)

Why Do We Need Git?

Solving the everyday chaos of software development

Problems vs Solutions

❌ Life Without Git

  • ✕ Accidentally deleting working code with no undo
  • ✕ Losing earlier working versions permanently
  • ✕ Not knowing who broke a feature or when
  • ✕ Painful file naming madness:
📄 project-final.zip
📄 project-final2.zip
📄 project-final-real.zip
📄 project-final-real-final-v2.zip

✅ Life With Git

  • ✓ Single clean folder: No duplicate zipped copies
  • ✓ Time machine: Jump to any commit in history
  • ✓ Detailed attribution: Every change has an author and timestamp
  • ✓ Safe experiments: Try features in isolated branches
  • ✓ Team harmony: Merge contributions smoothly
Git records exact line-by-line diffs of every file you choose to save.

Slide 05 — Part 1: Installation

Check if Git Is Installed

Verifying your terminal environment before starting

Local Terminal
Terminal
$ git --version
git version 2.43.0
If a version number (like git version 2.x.x) is printed, Git is successfully installed on your machine!

What If Git Is Not Installed?

If your terminal responds with command not found: git, download and install it for your operating system:

  • macOS: Run xcode-select --install or install via Homebrew: brew install git
  • Windows: Download from git-scm.com (includes Git Bash)
  • Linux (Ubuntu/Debian): sudo apt install git
Slide 06 — Part 1: Installation

Basic Git Configuration

Introducing yourself to Git so your commits are attributed to you

Identity Setup
Terminal Setup
$ git config --global user.name "Your Name"
$ git config --global user.email "you@example.com"
$ git config --global --list
user.name=Your Name user.email=you@example.com

Why Does Git Need This?

These values are stamped onto every commit you create as the commit author. Collaborators and GitHub use this email to associate commits with your GitHub profile.

Important Distinction:
Git local identity (name/email) and GitHub authentication (passwords/tokens/SSH keys) are related, but not the same thing.

Slide 09 — Part 3: Check Project Status

git status

Your most important diagnostic command in Git

Inspection
Terminal: my-project
$ git status
On branch main No commits yet Untracked files: (use "git add <file>..." to include in what will be committed) README.md nothing added to commit but untracked files present (use "git add" to track)

What Does Untracked Mean?

Untracked = Git sees the file, but it is not being tracked yet.

Any changes you make to an untracked file will not be recorded until you explicitly tell Git to track it using git add.

Whenever you are unsure of what to do next, run git status. Git usually prints helpful suggestions!
Slide 10 — Part 4: Staging

git add

Selecting and preparing files for the next snapshot

Staging Area
Stage Specific File
$ git add README.md
Stage All Files At Once
$ git add .
Working Directory Unstaged files
git add ➔
Staging Area Ready to commit

Why Have a Staging Area?

Staging acts like a buffer. If you modified 5 files but only want 2 of them in this commit, staging allows you to craft precise, clean commits.

Slide 11 — Part 4: Staging

Check the Staged Changes

Verifying that files moved into the staging area

Status: Staged
Terminal: git status
$ git status
On branch main No commits yet Changes to be committed: (use "git rm --cached <file>..." to unstage) new file: README.md

Green Means Staged!

Notice the color change: README.md is now listed under Changes to be committed in bright green.

This confirms the file is successfully staged and waiting to be permanently captured by git commit.

If you make further edits to README.md now, the new edits won't be staged until you run git add again!

Slide 13 — Part 5: Commit

View Commit History

git log
git log (Full View)
$ git log
commit a1b2c3d4e5f67890abcdef1234567890abcdef12 Author: Your Name <you@example.com> Date: Mon Oct 19 09:30:00 2026 +0700 Initial commit
git log --oneline (Compact View)
$ git log --oneline
a1b2c3d Initial commit

What Is a Commit Hash?

A commit hash (e.g. a1b2c3d) is a unique 40-character SHA-1 checksum that cryptographically identifies that exact snapshot and state in time.

You only need the first 7 characters to reference any commit in Git commands.

Slide 16 — Part 7: Connect Local Git to GitHub

Add GitHub Remote

Teaching your local repository the URL of your GitHub repository

Local ➔ Remote Link
Terminal: Connect Remote
$ git remote add origin https://github.com/USERNAME/my-project.git
$ git remote -v
origin https://github.com/USERNAME/my-project.git (fetch) origin https://github.com/USERNAME/my-project.git (push)

Anatomy of the Command

  • git remote: Manage remote connections
  • add: Register a new remote
  • origin: Standard default nickname for the primary remote
  • URL: The web address of your GitHub repository
git remote -v (verbose) lists all connected remotes and verifies the link.
Slide 17 — Part 7: Connect Local Git to GitHub

HTTPS vs SSH

Understanding the two common connection protocols

Protocols

🔒 HTTPS (Recommended for Beginners)

https://github.com/USERNAME/my-project.git
  • ✓ Works immediately out of the box
  • ✓ No complex key generation required
  • ✓ Authenticates via GitHub Personal Access Token (PAT) or Git Credential Manager browser login

🔑 SSH (Advanced / Experienced Devs)

git@github.com:USERNAME/my-project.git
  • ✓ Passwordless authentication via cryptographic keypairs
  • ✓ Preferred by developers for automated terminal workflow
  • ✕ Requires generating SSH keys and adding them to GitHub settings first
Slide 18 — Part 8: First Push

Rename Branch to main

Standardizing your primary branch name to match modern GitHub

Branch Configuration
Terminal: Rename Branch
$ git branch -M main
-M stands for "Move/Rename with Force". It renames your current branch to main regardless of what it was named before.

Why main?

Historically, Git defaulted to calling the first branch master. In 2020, GitHub and the open-source community transitioned to main as the official, modern industry standard default branch name.

Running git branch -M main ensures your local repository and GitHub's default branch name align seamlessly.

Slide 19 — Part 8: First Push

Push to GitHub

The pivotal command: uploading your local commits to the cloud

The Big Moment
Terminal: Push
$ git push -u origin main
Enumerating objects: 3, done. Counting objects: 100% (3/3), done. Writing objects: 100% (3/3), 220 bytes | 220.00 KiB/s, done. Total 3 (delta 0), reused 0 (delta 0), pack-reused 0 To https://github.com/USERNAME/my-project.git * [new branch] main -> main branch 'main' set up to track 'origin/main'.

Command Breakdown

  • git: Git CLI application
  • push: Upload local commits to remote
  • -u: Set upstream (remembers remote branch for future simple git push)
  • origin: Target remote server nickname
  • main: Local branch to upload
Local Repo Your computer
git push ➔
GitHub Remote Repo

The Everyday Git Workflow

The four commands developers execute dozens of times every single day

Core Loop
The Daily 4-Step Cycle
1. git status
Inspect what files changed
2. git add .
Stage all modified and new files

Slide 23 — Part 10: Clone an Existing Project

Clone a Repository

Downloading an existing repository and its full history from GitHub

Remote ➔ Local
Terminal: Clone
$ git clone https://github.com/USERNAME/my-project.git
Cloning into 'my-project'... remote: Enumerating objects: 6, done. remote: Total 6 (delta 0), reused 6 (delta 0) Receiving objects: 100% (6/6), done.
$ cd my-project

What Does git clone Do?

clone = download a Git repository and its complete commit history to your computer.

  • Creates a new folder matching the repository name
  • Downloads all project files and branches
  • Automatically sets up origin remote linking back to GitHub
  • You do NOT need to run git init!

Push vs Pull Direction

git push Uploads: Local ➔ Remote

What Is a Branch?

Creating isolated sandboxes for new features without breaking production

Branching
Branches let you work on experimental code without disturbing the stable main branch.

Why Developers Use Branches

  • ✨ New features: Develop isolated features without breaking existing code
  • 🐛 Bug fixes: Patch urgent bugs quickly without mixing unfinished work

Slide 26 — Part 11: Branches

Create and Switch Branch

Modern branch management syntax in Git

git switch
Modern Syntax (Recommended)
$ git switch -c feature/login
Switched to a new branch 'feature/login'
$ git switch main
Switched to branch 'main'

Older Equivalent Command

In older tutorials or blog posts, you will often see:

git checkout -b feature/login

git checkout had too many conflicting responsibilities (switching branches AND discarding file changes). Git introduced git switch in version 2.23 to be dedicated, clear, and beginner-friendly.

Slide 28 — Part 13: Common Mistakes

Mistake: Forgetting to Commit

Why running git add then git push doesn't upload your changes

Common Pitfall #1
The Mistake
$ git add .
$ git push
Everything up-to-date
git push only uploads commits! Staged files that are not committed yet will never be pushed.
The Correct Flow
$ git add .
$ git commit -m "Update project"
$ git push
To https://github.com/... a1b2c3d..d4e5f6g main -> main
Slide 29 — Part 13: Common Mistakes

Mistake: Wrong Remote URL

Fixing typos in repository URLs without deleting the repository

Common Pitfall #2
Check Current URL
$ git remote -v
origin https://github.com/WRONG-USER/wrong-repo.git (fetch) origin https://github.com/WRONG-USER/wrong-repo.git (push)
Fix with set-url
$ git remote set-url origin https://github.com/USERNAME/REPOSITORY.git

Why Not git remote add?

If you try running git remote add origin ... again when origin already exists, Git will error: fatal: remote origin already exists.

Use git remote set-url origin <new-url> to safely update the existing origin URL.

Slide 30 — Part 13: Common Mistakes

Mistake: Push Rejected

Understanding non-fast-forward rejections and why never to force push

Common Pitfall #3
Push Rejected Error
$ git push
! [rejected] main -> main (fetch first) error: failed to push some refs to 'https://github.com/...' hint: Updates were rejected because the remote contains work that you do not have locally.
The Solution: Pull First
$ git pull
$ git push
DO NOT BLINDLY USE:
git push --force
Force push overwrites and deletes the remote history on GitHub, potentially destroying work done by teammates!

Common Causes

  • A teammate pushed new commits to GitHub
  • The GitHub repo was created with an extra README/license
  • Running git pull merges remote changes into local first so you can push cleanly
Slide 31 — Part 14: .gitignore

What Is .gitignore?

Preventing junk, generated files, and secrets from entering your repository

Clean Repositories
Example .gitignore File
node_modules/ .env .next/ dist/ *.log .DS_Store

Why Is This Essential?

A .gitignore file is placed in the root of your project. Git will intentionally never track files matching these patterns.

NEVER COMMIT SECRETS:
Files like .env containing API keys, database passwords, or auth tokens must always be in .gitignore.
Slide 32 — Part 14: .gitignore

Example Project Structure

Visualizing what gets tracked vs what stays local

Folder Layout
📁 my-project/
├── 📁 .git/ (Internal database - stays local)
├── 📄 .gitignore (Pushed to GitHub)
├── 📄 README.md (Pushed to GitHub)
├── 📄 package.json (Pushed to GitHub)
├── 📁 src/ (Pushed to GitHub)
└── 📁 node_modules/ (IGNORED: Stays local)

Why Is node_modules/ Ignored?

In Node.js projects, node_modules/ can contain hundreds of thousands of downloaded package files and weigh gigabytes.

Anyone cloning your repository can reproduce the entire folder instantly by running pnpm install using the committed package.json.

The Mental Model

The four architectural layers of Git and how data travels between them

Core Architecture
GitHub (Remote Repository)
Hosted in the cloud on github.com
Remote
▲ git push (Upload)  |  ▼ git pull (Download)
Local Repository (.git)
Full commit history on your disk
Local
▲ git commit
Staging Area (Index)
Selected changes ready for next commit
Buffer
▲ git add
Working Directory
Actual files you see and edit in your IDE
Workspace

Why This Mental Model Matters

When you understand these 4 distinct layers, Git errors stop being mysterious.

You always know:

  • Where your changes currently live
  • Which command moves them to the next level
  • Whether a change is local or shared remotely
