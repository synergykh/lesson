OVERVIEW

What Is GitHub & Why Do We Need It?

Distinguishing between your local machine tool and the world's largest code platform

01 Git (Local Machine)

Git runs on your personal computer. It tracks file revisions, commits, and branches completely offline without requiring internet access.

Local git protects your work locally on one machine.

02 GitHub (Cloud Platform)

GitHub is a cloud service that hosts Git repositories online. It enables team collaboration, code reviews, issue tracking, continuous integration, and portfolio showcase.

GitHub allows anyone on your team to clone, review, and contribute to your repository.

Slide 16 — Part 7: Connect Local Git to GitHub

Add GitHub Remote

Teaching your local repository the URL of your GitHub repository

Local Remote Link
Terminal: Connect Remote
$ git remote add origin https://github.com/USERNAME/my-project.git
$ git remote -v
origin https://github.com/USERNAME/my-project.git (fetch) origin https://github.com/USERNAME/my-project.git (push)

Anatomy of the Command

  • git remote: Manage remote connections
  • add: Register a new remote
  • origin: Standard default nickname for the primary remote
  • URL: The web address of your GitHub repository
git remote -v (verbose) lists all connected remotes and verifies the link.
Slide 17 — Part 7: Connect Local Git to GitHub

HTTPS vs SSH

Understanding the two common connection protocols

Protocols

HTTPS (Recommended for Beginners)

https://github.com/USERNAME/my-project.git
  • Works immediately out of the box
  • No complex key generation required
  • Authenticates via GitHub Personal Access Token (PAT) or Git Credential Manager browser login

SSH (Advanced / Experienced Devs)

git@github.com:USERNAME/my-project.git
  • Passwordless authentication via cryptographic keypairs
  • Preferred by developers for automated terminal workflow
  • Requires generating SSH keys and adding them to GitHub settings first
Slide 18 — Part 8: First Push

Rename Branch to main

Standardizing your primary branch name to match modern GitHub

Branch Configuration
Terminal: Rename Branch
$ git branch -M main
-M stands for "Move/Rename with Force". It renames your current branch to main regardless of what it was named before.

Why main?

Historically, Git defaulted to calling the first branch master. In 2020, GitHub and the open-source community transitioned to main as the official, modern industry standard default branch name.

Running git branch -M main ensures your local repository and GitHub's default branch name align seamlessly.

Slide 19 — Part 8: First Push

Push to GitHub

The pivotal command: uploading your local commits to the cloud

The Big Moment
Terminal: Push
$ git push -u origin main
Enumerating objects: 3, done. Counting objects: 100% (3/3), done. Writing objects: 100% (3/3), 220 bytes | 220.00 KiB/s, done. Total 3 (delta 0), reused 0 (delta 0), pack-reused 0 To https://github.com/USERNAME/my-project.git * [new branch] main -> main branch 'main' set up to track 'origin/main'.

Command Breakdown

  • git: Git CLI application
  • push: Upload local commits to remote
  • -u: Set upstream (remembers remote branch for future simple git push)
  • origin: Target remote server nickname
  • main: Local branch to upload

Slide 21 — Part 9: Making Future Changes

The Everyday Git Workflow

The four commands developers execute dozens of times every single day

Core Loop
The Daily 4-Step Cycle
1. git status
Inspect what files changed
2. git add .
Stage all modified and new files
3. git commit -m "Describe your changes"
Record snapshot with a clear message
4. git push
Upload new commit to GitHub!

Why Memorize This Loop?

Whether you are building a small personal website or working at a tech giant with 10,000 engineers, this 4-step sequence is the heart of everyday version control.

Because you used -u earlier, you only need to type git push without specifying remote and branch names every time!

Slide 23 — Part 10: Clone an Existing Project

Clone a Repository

Downloading an existing repository and its full history from GitHub

Remote Local
Terminal: Clone
$ git clone https://github.com/USERNAME/my-project.git
Cloning into 'my-project'... remote: Enumerating objects: 6, done. remote: Total 6 (delta 0), reused 6 (delta 0) Receiving objects: 100% (6/6), done.
$ cd my-project

What Does git clone Do?

clone = download a Git repository and its complete commit history to your computer.

  • Creates a new folder matching the repository name
  • Downloads all project files and branches
  • Automatically sets up origin remote linking back to GitHub
  • You do NOT need to run git init!

Pull Changes

Syncing your local workspace with updates made by teammates or other machines

Remote Local
Terminal: Pull
$ git pull
Updating a1b2c3d..e7f8g9h Fast-forward README.md | 2 +- 1 file changed, 1 insertion(+), 1 deletion(-)
GitHub New commits
git pull
Your Computer Updated working tree

Push vs Pull Direction

git push Uploads: Local Remote
git pull Downloads: Remote Local
Always run git pull before starting work on a team project to avoid conflicting commits!
Slide 29 — Part 13: Common Mistakes

Mistake: Wrong Remote URL

Fixing typos in repository URLs without deleting the repository

Common Pitfall #2
Check Current URL
$ git remote -v
origin https://github.com/WRONG-USER/wrong-repo.git (fetch) origin https://github.com/WRONG-USER/wrong-repo.git (push)
Fix with set-url
$ git remote set-url origin https://github.com/USERNAME/REPOSITORY.git

Why Not git remote add?

If you try running git remote add origin ... again when origin already exists, Git will error: fatal: remote origin already exists.

Use git remote set-url origin <new-url> to safely update the existing origin URL.

Slide 30 — Part 13: Common Mistakes

Mistake: Push Rejected

Understanding non-fast-forward rejections and why never to force push

Common Pitfall #3
Push Rejected Error
$ git push
! [rejected] main -> main (fetch first) error: failed to push some refs to 'https://github.com/...' hint: Updates were rejected because the remote contains work that you do not have locally.
The Solution: Pull First
$ git pull
$ git push
DO NOT BLINDLY USE:
git push --force
Force push overwrites and deletes the remote history on GitHub, potentially destroying work done by teammates!

Common Causes

  • A teammate pushed new commits to GitHub
  • The GitHub repo was created with an extra README/license
  • Running git pull merges remote changes into local first so you can push cleanly
