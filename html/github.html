Git (Local Machine) vs. GitHub (Cloud Platform)

Distinguishing between your offline CLI engine and the world's largest developer platform

Local vs. Cloud
01

Git (The Engine)

  • ✓ Installed on your local operating system
  • ✓ 100% offline, requires zero internet access
  • ✓ Manages commit history inside .git/
  • • Cannot share code with others on its own
02

GitHub (The Cloud)

  • ✓ Cloud hosting platform for Git repositories
  • ✓ Team Pull Requests & Code Review
  • ✓ Automated CI/CD via GitHub Actions
  • ✓ Issue tracking, Kanban boards & security scans

PART 06 • PULL REQUESTS

Merging Strategies: Merge Commit vs. Squash vs. Rebase

Choosing the right merge technique to maintain a pristine production history

3 Merge Types
1. Create a Merge Commit git merge --no-ff

Preserves every individual commit from the feature branch. Creates a 2-parent merge commit on main. Can make history busy if branches have many "wip" commits.

2. Squash and Merge (Industry Favorite) Recommended

Squashes 10 messy feature commits ("fixed typo", "debug logging") into 1 clean commit on main. Perfect for clean Git logs and atomic rollbacks.

3. Rebase and Merge Linear History

Appends individual commits directly onto tip of main without a merge commit. Produces a 100% linear history.

PART 07 • CLONING & CONTRIBUTING

Forks & Open Source Contribution Workflow

Contributing to public repositories you don't own with upstream sync

Fork & Upstream

5-Step Open Source Contribution Cycle

  • 1 Fork: Click "Fork" on GitHub to make a personal copy in your account.
  • 2 Clone: Clone your personal fork to your computer: git clone <fork-url>.
  • 3 Add Upstream: git remote add upstream <original-repo-url>.
  • 4 Branch & Push: git checkout -b fix-bug, commit, and push to your fork.
  • 5 Open PR: Submit a Pull Request from your fork back to the upstream repo!
Syncing your fork: Run git fetch upstream && git merge upstream/main to keep your personal fork up to date with new releases from the main team.

PART 08 • CONFLICT RESOLUTION

Resolving Merge Conflicts on GitHub & Locally

Understanding conflicting changes when team members edit the same lines of code

Conflict Fix
Conflict Markers in File app.js
<<<<<<< HEAD (Current Change - Your Branch)
const port = process.env.PORT || 3000;
======= (Divider)
const port = process.env.PORT || 8080;
>>>>>>> origin/main (Incoming Change - Teammate)
Resolution in 3 Steps: 1. Decide which version to keep (or combine both). 2. Delete all marker lines (<<<<<<<, =======, >>>>>>>). 3. Run git add . && git commit -m "fix: resolve port conflict" && git push.

PART 11 • BEST PRACTICES

Top 5 GitHub Beginner Errors & Instant Fixes

Practical troubleshooting solutions for the most frequent command errors

Troubleshooting
1. "error: failed to push some refs" Remote has commits you don't have. Fix: git pull --rebase origin main then push.
2. "fatal: remote origin already exists" Remote URL registered twice. Fix: git remote set-url origin <new-url>.
3. Commits not linked to your GitHub avatar Config email doesn't match GitHub. Fix: git config --global user.email "your@github.com".
4. "Support for password authentication was removed" GitHub requires SSH or PAT. Fix: Add SSH key or Personal Access Token.
5. Safely undoing a pushed bad commit Never force push on shared branches. Fix: git revert <commit-hash> && git push.
