OVERVIEW

Why Next.js Over Plain React?

Solving the limitations of traditional Single-Page Applications (SPAs)

❌ Traditional Client React (Vite/CRA)

Browser downloads a blank HTML file and a giant JavaScript bundle. The user stares at a white loading screen before any content renders.

Poor initial SEO, slow first contentful paint (FCP) on mobile networks.

✔ Next.js Fullstack Architecture

HTML is generated on the server and delivered instantly. Search engines read complete content, and React hydrates interactivity in the background.

Built-in routing, image optimization, API routes, and Server Components with 0kB client JS.

ARCHITECTURE

App Router Directory Structure

Understanding special files in the app folder

📁 dev-portal/
├── 📁 src/app/
│ ├── 📄 layout.tsx (Root shell for all pages)
│ ├── 📄 page.tsx (Route: / Home Page)
│ ├── 📄 loading.tsx (Automatic Suspense fallback)
│ ├── 📄 error.tsx (Client error boundary)
│ └── 📁 dashboard/
│ └── 📄 page.tsx (Route: /dashboard)
├── 📁 public/ (Static images, fonts, icons)
└── 📄 package.json

Core App Router Rules

1. page.tsx defines publicly accessible routes based on folder names.

2. layout.tsx wraps pages and preserves UI state across navigation.

3. Folders without a page.tsx do not expose a public route.

COMPONENTS

Server Components vs Client Components

The foundational concept of React 19 in Next.js

Server Component (Default)
// Runs on server only. 0kB client JS!
// Direct database or backend access.
export default async function ProductList() {
  const products = await db.products.findMany();

  return (
    <div className="grid grid-cols-3 gap-4">
      {products.map(p => (
        <div key={p.id}>{p.name}</div>
      ))}
    </div>
  );
}
Client Component ('use client')
'use client'; // Required for browser APIs

import { useState } from 'react';

export default function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      Count: {count}
    </button>
  );
}

DATA FETCHING

Async Data Fetching in Server Components

Direct async/await without useEffect or client libraries

app/users/page.tsx
interface User {
  id: number;
  name: string;
  email: string;
}

export default async function UsersPage() {
  const res = await fetch('https://jsonplaceholder.typicode.com/users', {
    next: { revalidate: 3600 } // Cache data for 1 hour
  });
  const users: User[] = await res.json();

  return (
    <div className="p-6">
      <h1 className="text-2xl font-bold mb-4">Team Members</h1>
      <ul className="space-y-2">
        {users.map(user => (
          <li key={user.id} className="p-3 bg-slate-800 rounded-md">
            {user.name} ({user.email})
          </li>
        ))}
      </ul>
    </div>
  );
}
API ROUTES

Route Handlers (Backend in Next.js)

Building custom API endpoints inside the app directory

app/api/contact/route.ts
import { NextResponse } from 'next/server';

export async function POST(request: Request) {
  const body = await request.json();
  const { email, message } = body;

  if (!email || !message) {
    return NextResponse.json({ error: 'Missing fields' }, { status: 400 });
  }

  // Save to database or send email...
  return NextResponse.json({ success: true, received: body }, { status: 201 });
}

export async function GET() {
  return NextResponse.json({ status: 'API is running' });
}
Endpoints are accessed at http://localhost:3000/api/contact. Supports GET, POST, PUT, DELETE, PATCH.
