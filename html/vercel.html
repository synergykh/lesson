PART 01 • EXECUTION MODELS

Static Websites vs Fullstack Applications

Understanding execution models: Static Files, SSR, and Serverless APIs

Static Sites (SSG / HTML)

Pure HTML, CSS, and JS generated ahead of time during build. Served directly from Edge CDN storage with zero server computation.

Server-Rendered (SSR)

HTML is rendered on-demand for every visitor request via Serverless Functions. Ideal for dynamic dashboards and personalized feeds.

Serverless APIs & Actions

Isolated backend compute executing on demand without maintaining continuous servers. Scales from 0 to thousands of concurrent requests.

PART 10 • SECURITY BOUNDARY

The NEXT_PUBLIC_* Security Boundary

Preventing client bundle leakage of private server secrets

CRITICAL

Server-Only (Secret)

DATABASE_URL, STRIPE_SECRET_KEY

Never prefixed with NEXT_PUBLIC_. Only accessible inside Server Components, Route Handlers, and Server Actions.

Client-Exposed (Public)

NEXT_PUBLIC_APP_NAME, NEXT_PUBLIC_MAP_KEY

Inlined directly into browser JavaScript bundle during build. Accessible by anyone viewing website source.

PART 13 • EMAIL SAFETY

Preserving Email DNS Records

Avoiding email disruption by protecting MX, SPF, DKIM, and DMARC

DANGER ZONE
NEVER DELETE MX RECORDS! If you have Google Workspace or Outlook email connected to your domain, only add the required A or CNAME record. Do not switch nameservers or wipe existing MX, TXT (SPF), or DKIM records, or company email will break instantly.

PART 15 • THE MIGRATION TRAP

The Code vs Database Rollback Discrepancy

Why rolling back code does NOT undo database schema changes

CRITICAL WARNING
Vercel rollback ONLY reverts web frontend and serverless code! It cannot un-drop database tables or rollback destructive SQL migrations on Neon. Design migrations to be backward-compatible with the previous release.

Top 10 Costly Deployment Mistakes
